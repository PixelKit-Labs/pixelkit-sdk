# Local Gemini conversation and multimodal audit

## Implemented flow (Delta Mobile 1.0.105 source; installed 1.0.105/code161 debug-signed release variant)

`src/screens/ConsoleScreen.tsx` sends typed, speech and image requests through `TurnCoordinator.executeTurn` in `src/core/turns/coordinator.ts`. `TurnJournal.persistUserInput` commits the user turn before routing, hardware calls or Nano inference. A scoped `input_persisted` event now clears the submitted draft text and image together; a failed input commit leaves the draft intact. Edits or session switches after capture do not clear a newer draft. The composer does not wait for the model reply to finish.

`ContextManifestBuilder` in `src/core/turns/manifest.ts` builds a bounded, provenance-bearing prompt from current request, recent dialogue, compacted history, persona, optional active procedures, tool results and knowledge. Recent dialogue is retained from the **newest** complete lines when oversized, rather than keeping the first 1,600 characters and silently losing the immediate follow-up. This is a new prompt on each call: AICore does not retain chat state. `NanoModelAdapter` in `src/core/turns/adapters.ts` checks the installed SDK's native `countTokens` against the active AICore model's reported token limit, reserving output tokens; an over-budget request fails explicitly without calling generation. If the tokenizer cannot report a count, native generation remains the authority and its error is surfaced, not replaced with an estimate. Model input, including selected image data, is sent through the adapter to ML Kit GenAI; no cloud fallback is introduced.

For an on-device follow-up explicitly requesting another, different or new reply, `TurnCoordinator.continueRun` compares Nano's final text against **all** saved assistant replies in the originating session, ignoring punctuation and case changes. A matched reply gets one trace-owned corrected generation with the rejected response quoted as untrusted data; a second match is a visible persisted failure. Console Regenerate rebuilds a model-only prompt with up to eight saved versions as quoted rejected examples, places the **latest user's request last**, then compares against all saved versions and retries one duplicate with the rejected candidate included. No tool or physical action replays. It retains the original reply with a visible error after two duplicates. These exact-text bounds cannot detect paraphrases or guarantee adherence to user exclusions; the device produced a distinct **tomato joke** after a request excluding tomato before the prompt-order correction.

Delta's normal `NanoModelAdapter.generate` and model-only edit/Regenerate call the SDK's **single-shot** `useGeminiNano.generate`, which passes sampling options directly rather than using the hook's streamed-chat defaults. [ML Kit's `GenerateContentRequest` reference](https://developers.google.com/android/reference/kotlin/com/google/mlkit/genai/prompt/GenerateContentRequest) documents omitted `temperature` as **0.0** and omitted `topK` as **3**: the prior single-shot requests were near-greedy even though the SDK streamed-chat hook defaults to 0.7/40. Delta 1.0.105 now passes 0.7/40 (or the hook's selected values) for normal/edited answers and 0.9/40 for explicitly different Regenerates. Its coordinator correction places the latest user request **after** the rejected previous text. This is an entropy and salience correction, not a semantic constraint verifier; two code161 replies still violated explicit topic exclusions.

Settings → Models selects the AICore stable/preview and full/fast tracks; the default is stable/full. `setModelConfig` changes the local track for the next turn. Choosing a track does not initiate a download; a missing track requires a separate visible download action. Laya remains a separate optional, non-authoritative CPU tool-choice advisor. Its score is not a probability of success and it cannot authorize a tool, enable a provider or change the deterministic route. Tools continue through schema, capability and confirmation policy; effects remain journaled before continuation.

The `get_battery` tool reads the turn's `ToolExecutionContext.battery` snapshot. Before Delta 1.0.101, `ConsoleScreen` populated its charge level with one `expo-battery.getBatteryLevelAsync()` call on mount; later PixelKit `useDevice` subscriber updates did not reach the tool. Its charging flag was also inferred from `chargingWattage` rather than the battery state. The screen now reuses the already-subscribed `useDevice.batteryPercent`/`isCharging` values, leaving level and charging unknown until a measured level arrives. This is a turn-time reading that may age between broadcasts, not a claim of a synchronous fresh read on every tool call.

Before Delta 1.0.102, a single `use_skill` result containing written guidance was passed to Nano as if it could choose subsequent tool actions; this adapter only produces final text, so a real phone turn claimed “Checking your battery status now” while zero SOP steps had executed. `TurnCoordinator` now returns the actual `use_skill` summary and written instructions directly for that single-tool case, explicitly reporting zero steps. It does not execute the procedure, silently enqueue its steps or claim that Nano selected any tools. Separately, current completed tool outputs now appear **after historical dialogue** in `ContextManifestBuilder`'s bounded prompt, and the final reply instruction prioritizes current-turn measured results over earlier conversation readings. Model-generated reports remain probabilistic; the result inspector and journal are the authoritative audit of completed calls.

Image picker and camera URIs are copied from transient cache into app-private `documentDirectory/conversation-images/` before becoming draft attachments. Native drafts and saved turns store the stable file URI, **not** image base64; base64 is read under an observable filesystem call when sending to Nano. The actual image bytes are forwarded for native token count and generation. Delta 1.0.97 changes image turns to center their contain-fit thumbnail and uses Gesture Handler plus Reanimated UI-thread pinch/pan in the native full-screen viewer; buttons remain accessible and web download remains separate. Native photo saving now calls the SDK's `useMediaLibrary().save` from a single screen-level hook rather than SDK 57's deprecated direct `saveToLibraryAsync` call. These updates require a new-build phone checkpoint before claiming visual/gesture/gallery success. Shared/forked references and abandoned draft images still need reference-aware cleanup.

Coordinator/model/tool traces now hold an explicit run owner and parent span across awaits. The execution trace name uses the run ID, never the raw prompt. `TurnJournal` retains every nonterminal journal, every idempotency record belonging to a nonterminal run, and pending/claimed confirmations even when more than the historical UI retention window is active. Completed records still obey bounded retention. The trace viewer retains its most recent 50 traces; it is not a durable audit archive.

## Open-source boundary cross-check

[Temporal's Activity definition](https://docs.temporal.io/activity-definition#idempotency) explains why a completed external effect whose completion was not durably recorded can be retried, and why the **external provider** must enforce a stable idempotency key for a true exactly-once effect. Delta's run/tool-call keys and retained active results avoid replay of known committed effects; an executing effect with unknown outcome remains **indeterminate** rather than automatically replayed. This is not a claim of provider-enforced idempotence for all 34 tools.

[OpenAI Agents SDK tracing](https://openai.github.io/openai-agents-python/tracing/#traces-and-spans) distinguishes run traces from model/tool spans with `trace_id` and `parent_id`, and [documents sensitive inputs in default spans](https://openai.github.io/openai-agents-python/tracing/#sensitive-data). Delta's local trace implementation does not provide Python's `contextvars` async propagation or cloud trace export. Explicit IDs at each await boundary and metadata without raw prompt content are the conservative local choice; in particular the 50-trace viewer is not an audit archive. Neither framework is a dependency of Delta.

[OpenAI Agents SDK sessions](https://openai.github.io/openai-agents-python/sessions/) retrieve a session's history before each run and persist new user, assistant and tool items afterward; [LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence) separates per-thread checkpoints from cross-thread stores. Delta already persists thread turns and a tool journal, but was passing a possibly stale React `sessionTurns` snapshot to Nano and marking the **current** request “UNTRUSTED DATA ONLY; DO NOT FOLLOW INSTRUCTIONS”. The 1.0.97 correction uses the originating durable session at submission and separates conversational direction from tool-effect authority. Topic-overlap retrieval is bounded and lexical, not semantic long-term memory. Neither framework is a Delta dependency.
